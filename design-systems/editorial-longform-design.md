## 系统定位与适用范围

Editorial Longform 是一套编辑出版物式的中文长文网页系统。它将已经整理完成的内容呈现为可连续滚动、适合深度阅读、快速扫读、长期保存和轻量分享的独立 HTML 文档。

适用：

- 课程笔记、视频或播客总结；
- 深度文章、方法论、知识整理；
- 需要目录、时间轴、案例、截图和检查清单的长文；
- 阅读时长约 5–30 分钟的内容。

不适用：

- 横向翻页演示、数据后台、复杂交互应用；
- 强转化营销页、销售导向提案；
- 只包含一屏信息的短内容；
- 需要实时数据或账户功能的 Web 应用。

## 核心设计原则

1. **内容结构先于装饰。** 视觉只放大内容中已经存在的层级。
2. **中性色承担阅读，单一强调色承担信号。** 不用多色制造虚假丰富度。
3. **用留白建立章节节奏。** 优先用间距和分割线，不堆叠卡片。
4. **密度需要变化。** 正文、重点块、表格、图片和清单交替出现，避免连续同构模块。
5. **强调是一种稀缺资源。** 深色块只给核心框架、决定性结论或关键问题。
6. **本地优先。** 使用系统字体、内嵌 CSS 和相对资源路径，不依赖在线运行时。

## 视觉人格

- 安静、清楚、有编辑判断；
- 像一本经过设计的课程讲义或数字杂志；
- 温暖但不怀旧，现代但不科技炫技；
- 有明显层级，却不把每段内容包装成组件；
- 视觉服务于阅读，不抢占内容注意力。

## 内容适配建议

这些建议只用于判断排版适配度，不要求本系统改写内容：

- 最好有明确标题、导读和章节层级；
- 开头可包含摘要、阅读价值或元信息；
- 时间信息适合表格；步骤适合有序列表；比较关系适合表格；
- 案例应在说明附近放置对应图片；
- 结尾适合检查清单、行动建议或价值提炼；
- 如果内容没有可辨认层级，先由上游完成编辑，不用视觉组件掩盖结构缺失。

## 阅读节奏与信息密度

### 基本节奏

以“展开—停顿—强调—展开”为主要循环：

1. 章节标题提供明显停顿；
2. 两至六段正文展开论述；
3. 列表、表格或图片改变密度；
4. 真正重要时才用深色重点块；
5. 回到正文，避免连续多个强组件。

### 使用频率

- 每个一级章节通常只需要一种主要强调方式；
- 不连续放置两个深色重点块；
- 三个以上重复字段才优先使用表格；
- 图片紧随其解释出现，不创建与内容无关的画廊；
- 短段落不强行装入卡片；
- 一个视口内尽量只出现一个最高对比焦点。

## Design Tokens

### Colors

| Token | Value | Use |
|---|---|---|
| `--paper` | `#f3f0e8` | 页面暖灰纸张背景 |
| `--ink` | `#171816` | 正文和主要标题 |
| `--muted` | `#62645f` | 元信息、目录和次要说明 |
| `--line` | `#d5d0c3` | 分割线、边框 |
| `--card` | `#fbf9f3` | 表格、低强度提示背景 |
| `--accent` | `#ff5a36` | 唯一高饱和强调色 |
| `--accent-soft` | `#ffe1d7` | 代码、轻提示背景 |
| `--dark` | `#20231f` | 核心观点和表头 |

色彩规则：正文不用纯黑，页面不用纯白；强调色不用于大段正文；新增颜色必须解决当前 Token 无法表达的语义，而不是装饰。

### Width and spacing

| Token / Rule | Value |
|---|---|
| 页面最大宽度 | `1180px` |
| 桌面侧栏 | `250px` |
| 两栏间距 | `52px` |
| 页面内边距 | `36px 30px 80px` |
| 二级章节上间距 | `78px` |
| 小屏断点 | `850px` |

间距使用 4px 基础节奏，常用值为 8、12、16、20、24、28、36、38、52、58、78px。不要为了填满空间平均分布所有模块。

## 页面布局

桌面端采用 250px Sticky 目录加弹性正文的双栏 Grid。页面整体居中，最大宽度 1180px。正文列自然限制行长，不额外拉伸至全屏。

侧栏：

- 顶部显示文档类型和简短标题；
- 导航只列最有价值的一级节点，不复制全文目录；
- 默认使用次要文字色，Hover 使用强调色；
- 保持安静，不与文章争夺注意力。

正文：

- 主标题宽大但只出现一次；
- 章节依靠上方大留白和 2px 顶线分隔；
- 避免正文容器内再嵌套大量有边框容器。

## 字体层级

使用系统无衬线字体栈：

```css
-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
"Hiragino Sans GB", "Microsoft YaHei", sans-serif
```

| Role | Size / rule | Rhythm |
|---|---|---|
| 主标题 H1 | `clamp(36px, 6vw, 72px)` | `1.04` 行高，`-.04em` 字距 |
| 章节 H2 | `clamp(25px, 3vw, 37px)` | `1.25` 行高，`-.02em` 字距 |
| 子标题 H3 | `21px` | `1.35` 行高 |
| 正文 | 浏览器基准字号 | `1.78` 行高 |
| 导读 | `19px` | 保持正文行高 |
| 元信息 / 目录 | `12–13px` | 用颜色和字距降级 |

标题行高紧，正文行高松。不要通过连续增加字号建立所有层级；颜色、间距、字重和边线共同参与层级表达。

## 组件规范

### Hero

包含英文或类型眉题、唯一 H1、可选导读。眉题使用 12px、强调色、加大字距和全大写风格。

### Section Heading

H2 上方使用 2px 深色横线和大留白，承担章节换页般的停顿。H3 不使用卡片，仅靠字号和间距建立层级。

### Metadata Note

使用浅卡片背景、细边框、13px 次要文字。适合来源、作者、时长、更新时间等辅助信息，不承担核心观点。

### Key Statement

深色背景、白字、左侧 7px 强调色竖线，字号约 19px。只放一句框架、关键判断或决定性问题；不能作为普通段落容器。

### Inline Emphasis

使用加粗加 3px 强调色下划线，不把整句改成强调色。每段最多强调一到两个短语。

### Table

浅色表体、深色表头、仅保留必要水平分割线。单元格顶部对齐，14px 字号。用于时间轴、比较、映射和重复字段，不用于两三条简单列表。

### Image and Caption

图片与正文同宽，无阴影、无夸张圆角，只有 1px 边框。图片前后留出明显停顿。Caption 使用 12–13px 次要文字，并说明图片与论点的关系。

### Checklist

适合文章末段的行动检查或自检。复选框使用强调色；不要把普通项目符号列表伪装成清单。

### Lists

步骤使用有序列表，并列观点使用无序列表。列表项垂直间距约 5px，避免每项单独卡片化。

## 语义到组件的映射

| Existing semantic role | Component |
|---|---|
| 文档类型、栏目名 | Hero eyebrow |
| 文章唯一主题 | H1 |
| 来源、作者、时长 | Metadata Note |
| 文章导读 | Lead paragraph |
| 一级论述单元 | H2 Section Heading |
| 局部论点或步骤名 | H3 |
| 决定性框架或关键问题 | Key Statement |
| 短语级重点 | Inline Emphasis |
| 时间轴、多项比较、字段映射 | Table |
| 顺序过程 | Ordered list |
| 并列事实或建议 | Unordered list |
| 解释性画面 | Image + Caption |
| 可执行检查项 | Checklist |

如果一个内容块同时符合多个组件，选择最低视觉强度但仍能清楚表达语义的组件。

## 图片与表格规则

### 图片

- 使用有意义的 `alt`；
- 采用相对路径，HTML 与资源文件夹可一起移动；
- 不拉伸小图，不为装饰而重复截图；
- 裁切应保留支撑论点的界面或信息；
- 相邻图片表达同一组信息时才使用网格，默认仍为单列。

### 表格

- 第一列保持可扫描，表头短而明确；
- 手机上允许横向滚动；
- 大段叙述不要塞进单元格；
- 只有一组简单键值时使用列表或元信息块；
- 不用斑马纹、渐变或多色表头。

## 响应式与打印

### Responsive

850px 以下：

- 双栏改为单栏；
- Sticky 侧栏恢复普通文档流；
- 隐藏详细侧栏导航，保留品牌信息；
- 页面内边距缩至 `24px 18px 64px`；
- H2 上间距缩至 58px；
- 表格允许横向滚动。

### Print

- 页面背景改白；
- 隐藏顶部色条和侧栏；
- 移除外部链接装饰；
- H2/H3 避免孤立在页尾；
- 图片、表格和重点块尽量不跨页断开。

## 可访问性

- 保持正文与背景高对比度；
- 不只依赖颜色表达语义，强调同时使用线、位置或字重；
- 所有信息图片提供 alt；装饰图使用空 alt；
- 标题层级顺序使用，不跳级；
- 导航链接与目标 ID 一一对应；
- 正文不小于浏览器默认字号，次要文字不低于 12px；
- 不使用自动播放、闪烁或依赖 Hover 才能获取的信息。

## Do / Don't

### Do

- 用大留白区分章节；
- 让正文保持连续阅读感；
- 使用一种高饱和强调色；
- 在真正关键的位置切换为深色块；
- 让表格、图片和清单承担明确的信息任务；
- 保持 HTML 独立、可移动、可打印。

### Don't

- 不把每段内容变成圆角卡片；
- 不增加渐变、玻璃拟态、阴影和装饰图标；
- 不连续使用多个高对比组件；
- 不为“丰富”而混用多种强调色；
- 不使用在线字体或运行时 CSS/JS 依赖；
- 不为了适配模板而改写、夸大或补充内容。

## 扩展规则

当前主题固定。可以集中修改 Design Tokens 做内部维护，但不得在第一版产物中提供主题切换。

未来派生主题必须保持：

- 相同的语义组件模型；
- 相同的层级和阅读节奏原则；
- 相同的响应式、打印和可访问性底线；
- 独立的系统 ID、Design MD、模板和真实项目验证记录。

如果输出目的、阅读路径或媒介发生根本变化，应创建新的设计系统，而不是把 Editorial Longform 无限参数化。

## 质量检查清单

### 内容结构

- [ ] 文章只有一个 H1，H2/H3 层级连续。
- [ ] 目录只包含高价值章节，并与锚点匹配。
- [ ] 没有为了排版而新增事实、数据或观点。

### 视觉节奏

- [ ] 章节之间有足够停顿，正文没有形成连续文字墙。
- [ ] 深色重点块稀缺且用于真正重要的内容。
- [ ] 没有连续堆叠多个最高对比组件。
- [ ] 表格、图片和列表都有明确语义任务。

### 技术完整性

- [ ] CSS 内嵌，系统字体可用，无外部运行时依赖。
- [ ] 图片使用相对路径并具有 alt。
- [ ] 所有目录锚点有效。
- [ ] 850px 以下为可读单栏，表格不会撑破页面。
- [ ] 打印时隐藏侧栏并避免关键组件跨页。
- [ ] HTML 与资源文件夹一起移动后仍能打开。
